# Quality gates

Every change to this repository goes through checks that run on their own. This folder
explains them for someone seeing the repository for the first time: what runs on a pull
request, what each check proves, and what it protects on the pages a visitor sees. Each
page is short. Each diagram names the file it was drawn from, so you can check it.

## What runs on a pull request

<Mermaid
  chart={`
flowchart LR
    PR["Pull request opened or updated<br/>(drafts skip everything)"] --> C["checks<br/>matrix legs, in parallel"]
    PR --> S["sandcastle"]
    PR --> E["e2e"]
    PR --> V["visual-diff"]
    C --> G{"gate<br/>every result exactly success?"}
    S --> G
    E --> G
    G -->|"yes"| OK["gate green: mergeable"]
    G -->|"no: failure, cancelled or skipped"| NO["gate red: do not merge"]
    V -.->|"not in gate.needs"| R["Report + PR comment<br/>a person decides"]
`}
/>

Source: [`.github/workflows/pr.yml`](https://github.com/climaa/landing-lab/blob/main/.github/workflows/pr.yml),
the `gate` job's `needs:` and the `checks` matrix.

`gate` is the one check meant to be required. Today `main` has no branch rule that
enforces it, so a red `gate` is a clear signal rather than a lock. The same checks also run
on your machine before every push (`pnpm gate`, from `.husky/pre-push`).
