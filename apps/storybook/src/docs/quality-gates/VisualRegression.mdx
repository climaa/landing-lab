# Visual regression

The `visual-diff` job photographs every story in this Storybook and compares each
screenshot with the one committed in `packages/visual-diff/__baselines__/`. It answers one
question: did the interface move?

## Why it does not block a merge on its own

`visual-diff` is deliberately left out of `gate.needs`. When the interface moves, the job
fails its own check loudly and posts the report as a PR comment, but whether a moved pixel
is a bug or the point of the change is a judgment, not a threshold. The PR stays mergeable
on the `gate`'s results; the red `visual-diff` check is what tells the reviewer to look.
An intended change is accepted by committing the new baselines in the same PR (the
`accept-baselines` workflow, or `pnpm visual-diff:accept` locally), so the baseline and the
code change are reviewed together.

The same run checks every captured story with axe (WCAG 2.1 A and AA), and a violation is
its own bucket, `a11y`, even when the pixels match.

Documentation pages like this one are not captured: the differ photographs stories, and
drops docs entries before planning a capture. For the buckets and the report in detail, see
[Visual Diff Workflow](?path=/docs/docs-qa-visual-diff-workflow--docs).
